# Локальная политика ИСТК для BSL

Предметные нормы выбирать через [1c-standards.md](1c-standards.md). Здесь только особенности проекта; события, методы, контексты, запросы и СКД принадлежат своим руководствам.

- Изменения типовой логики выполнять в расширении по AGENTS. Собственные реквизиты/табличные части типовых объектов добавлять в основную конфигурацию с согласованным состоянием поддержки; расширение заимствует существующие реквизиты для привязки формы. Новые объекты размещать по AGENTS.
- В расширении обращаться к реквизитам объекта через `ЭтотОбъект.<Реквизит>`, к форме — через `ЭтотОбъект`; это позволяет избежать лишнего заимствования.
- Синоним собственного реквизита — человеческий заголовок без служебного префикса. Заголовок поля брать из метаданных, подсказку задать свойством реквизита; повтор в коде не нужен.
- Пользовательский текст локализовать через `НСтр`; сообщения выводить через проверенный API `ОбщегоНазначения.СообщитьПользователю` на сервере / `ОбщегоНазначенияКлиент.СообщитьПользователю` на клиенте. Сигнатуры сверять с реальной БСП; встроенное `Сообщить` не использовать вместо проектного механизма.
- Текущую серверную дату получать через `ТекущаяДатаСеанса()` по времени сеанса, а не времени машины. Это выбор проекта; `ТекущаяДата()` не объявляется удаленной из платформы.
- Журналирование определяет [logging-strategy.md](../skills/istk-rules/references/logging-strategy.md). Обработка ошибки сама по себе не разрешает добавлять новый журнал.

Изменения BSL по задаче помещать в блок; менять только дату и номер задачи, автора оставить:

```bsl
// ИСТК kazachkov.kl/Казачков КЛ {
// #10.02.2026 #SD-158824
// Код изменения.
// } ИСТК  kazachkov.kl/Казачков КЛ
```

Дата — текущая. Номер SD запросить, если отсутствует в задаче с изменением кода. Для документации/маршрутизации этот комментарий не требуется. После изменений применить gates AGENTS и чек-лист соответствующего типа; не дублировать их здесь.

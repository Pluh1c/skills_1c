# Методы, ответственность и API

Применять при создании/изменении метода, экспорта или размещения логики. Контекст и флаги модулей — [контексты](1c-contexts-and-modules.md); обработчики — [события](1c-events.md).

## Объектный подход в 1С

Работать через объектные инварианты и интерфейсы подсистем; новые классы и наследование в стиле другого языка не требуются.

| Ответственность | Где разместить | Пример |
|---|---|---|
| Конкретный экземпляр, включая незаписанное состояние | Модуль объекта | Проверить строки текущего документа, заполнить его реквизиты |
| Операция типа метаданных / сохраненной ссылки без загрузки экземпляра | Модуль менеджера | Получить данные печати по ссылкам |
| Несколько типов объектов, единая функция подсистемы | Общий модуль | Согласовать данные заказа и оплаты |
| Отображение, ввод, вызов предметного API | Модуль формы | Собрать параметры команды и показать результат |

Форма вызывает API; обработчик объекта охраняет инвариант независимо от формы. Менеджер не получает целый объект ради чтения пары полей: нужные данные читать пакетом по ссылкам. Для нескольких реквизитов ссылки получить набор за один вызов проверенного БСП API (например, `ЗначенияРеквизитовОбъекта`); для коллекции ссылок — пакетный API реальной версии библиотеки. Не разыменовывать каждую ссылку в цикле ради отдельных полей. Для БСП подобрать существующий экспорт по [1c-bsp-patterns.md](1c-bsp-patterns.md) и проверить его сигнатуру/версию.

## Рецепт метода

1. Найти существующую реализацию и потребителей через RLM/LSP. Определить одну ответственность и контекст.
2. Назвать действие: `ЗаполнитьТаблицу`; результат: `ДанныеПечати`; предикат: `ЕстьОшибки`; конструктор: `НовыйЗаказ`. Имена предметные (`Контрагенты`), встроенные глобальные имена оставить платформе.
3. Описать контракт: типы входов/результата, пустые значения, изменяемые параметры, исключения, права, транзакция и побочные эффекты. Проверять вариативный тип на границе, не в каждой внутренней процедуре.
4. Выбрать минимальную видимость. `Экспорт` — контракт для потребителей, а не настройка на всякий случай.
5. Выделить общий расчет в один метод; обработчики/команды делегируют ему. Явные ветви и ранний возврат делают основной путь читаемым.

```bsl
Функция РезультатПроверки(Знач ПроверкаПройдена, Знач ТекстОшибки = "")
	Возврат Новый Структура("ПроверкаПройдена,ТекстОшибки", ПроверкаПройдена, ТекстОшибки);
КонецФункции
```

Это пример собственного контракта. Связанные параметры, повторяемые в нескольких методах, объединять структурой с конструктором и описанными полями. Для вариантов предметного состояния использовать перечисление/определяемый тип, если они существуют в модели; строки оставить строковым данным.

`Знач` предотвращает обратную передачу присваивания параметру, но не делает глубокую копию массива/структуры/таблицы. Если метод меняет содержимое коллекции, документировать это либо создавать подходящую копию. Пустое значение и ошибка — разные исходы.

## Экспорт и совместимость

Порядок областей общего модуля: `ПрограммныйИнтерфейс` → `СлужебныйПрограммныйИнтерфейс` → `СлужебныеПроцедурыИФункции`; создавать только нужные области. Public — внешний стабильный контракт; служебный экспорт — контракт внутри библиотеки/подсистемы; private — реализация модуля. Переопределяемый API — точка расширения, учитывать существующие реализации.

Перед изменением экспорта найти вызовы, подписки и переопределения. При переименовании/удалении публичного метода оставить совместимую обертку и маршрут миграции. Новый обязательный параметр, иной тип или смысл результата требуют изменения потребителей либо совместимого адаптера. Проверять позиционные вызовы; необязательный параметр сам по себе не гарантирует совместимость поведения. Версионирование брать из реального контракта библиотеки, не навязывать всем локальным методам схему версии Unica.

## Данные, эффекты и читаемость

- Комментарий объясняет причину, ограничение или долг; явный алгоритм читается из кода.
- Строку держать до 120 символов при корректном переносе; метод ИСТК — до 200 строк. Делить по ответственности, не ради числа методов.
- Одно имя переменной — одно назначение; нормализовать входную коллекцию к одному типу, если это упрощает контракт.
- Ветвление писать `Если / ИначеЕсли / Иначе`. Для цепочки ИСТК явно определить поведение `Иначе`; осмысленно обработать неожиданный вариант, не вставлять пустую ветвь. Встроенный `?()` заменить читаемым `Если`; `ВЫБОР` принадлежит языку запросов/СКД.
- Запись в БД/изменение состояния выполнить отдельным вызовом; булево выражение использует его результат. Короткое замыкание `И`/`ИЛИ` тогда не пропускает операцию.
- Анализировать метод с эффектом вместе с местом вызова, правами и внешней транзакцией. Движения формировать через штатное проведение; подробности — [locks](../skills/istk-rules/references/locks-and-transactions.md).
- Повторяемое чтение/вычисление в цикле объединить пакетно либо кешировать `Соответствием`. Если `Неопределено` не входит в допустимые значения, `Кеш[Ключ] = Неопределено` означает отсутствие; иначе хранить обертку результата, различающую наличие и значение. Метод `СодержитКлюч` для `Соответствие` не придумывать.
- Ожидаемую ошибку обработать на границе ответственности; неожиданные исключения передать вызывающему коду. Журналирование задает один владелец — [logging](../skills/istk-rules/references/logging-strategy.md), без второго журнала на каждом уровне.
- Медленную операцию переносить в фоновый контур по измерению/требованию отклика, с отменой, статусом и обработкой ошибки. Универсального порога в 10 секунд нет. `Асинх` и версии — [async](../skills/istk-rules/references/async-methods.md).
- Динамическое исполнение, COM и внешние ресурсы выбирать только при обоснованном контракте/платформе. Секреты передавать через проектное защищенное хранение, пути формировать штатными функциями.

Дополнительный локальный стиль: отступ TAB; одна инструкция на строку; похожие присваивания локальным переменным можно выровнять, свойства объектов — обычными пробелами вокруг `=`. Составной пользовательский текст формировать через `СтрШаблон`, простые префикс/суффикс можно сложить. Положительные предметные имена, без смешения алфавитов и жаргона; отраслевые FIFO/FEFO/RLS/БСП допустимы. Крупный метод (>100 строк), глубокая вложенность (5+), высокая когнитивная сложность (15+) и 6+ параметров — сигналы пересмотреть ответственность и контракт, а не добавлять искусственные обертки. Вместо квадратичного поиска по коллекциям выбрать соответствие или подходящий индекс таблицы значений, если объем оправдывает стоимость построения.

Для экспортного метода (кроме предопределенной сигнатуры обработчика) описать назначение, типы параметров/возврата; у структуры — ключи, у массива — тип элемента. Пример формата:

```bsl
// Возвращает итог проверки.
// Параметры:
//  ПроверкаПройдена - Булево - итог предметной проверки.
// Возвращаемое значение:
//  Структура - ПроверкаПройдена, ТекстОшибки.
```

Для headless пакетной операции определить границу очистки/снятия буфера сообщений, чтобы сообщения предыдущего элемента не приписывались следующему; точный API проверить. Конкурентную запись согласовать с [locks](../skills/istk-rules/references/locks-and-transactions.md); блокировка объекта/данных редактирования и транзакционная блокировка решают разные задачи.

## Проверка

Рассмотреть реальные вызовы: обычный вход, пустой набор, ожидаемая ошибка, повторный вызов, изменяемая коллекция, сохраненный старый потребитель. Проверить соответствие ответственности и контракту; после BSL edit — диагностика из AGENTS. В потребительских runtime-тестах проверять результат и эффекты; без контура отметить их deferred.

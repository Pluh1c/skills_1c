# Создание и оптимизация запросов 1С

Этот документ — единственный источник правил создания и оптимизации запросов, включая запросы наборов данных СКД. Настройка отчета — [СКД](1c-skd.md); свидетельства приемки — [query-review.md](query-review.md).

## До написания

1. Через RLM проверить метаданные, имена и типы полей, существующие запросы и разрешенный API подсистемы. Если проверка недоступна, явно указать неподтвержденные допущения.
2. Определить ключ результата, детализацию, кратность строк, допустимые дубли, обработку пустых ссылок и `NULL`, границы периода и права пользователя.
3. Отбирать данные как можно раньше; выбирать только необходимые поля. Запросы по коллекции ключей выполнять вне цикла.
4. Связанные этапы выборки по возможности выполнять одним пакетным запросом. Для результата последнего запроса использовать `Выполнить()`, для нескольких результатов — `ВыполнитьПакет()`.
5. До оптимизации сохранить исходный результат, параметры и замеры; при доступности — план выполнения. Проверять эквивалентность под теми же правами и на тех же данных. Без проверки в рабочей среде ускорение остается гипотезой.

## Отборы и соединения

- Основные отборы и соединения строить по индексируемым полям. Учитывать состав и порядок полей индекса.
- Не оборачивать поля основного отбора в функции, `ВЫБОР` и приведения типов без необходимости. Вычисления от параметров по возможности выполнять до запроса.
- `В (подзапрос)` вне параметров виртуальных таблиц не использовать: подготовить ВТ ключей и применить соединение. При проверке наличия соответствия обеспечить уникальность ключей ВТ. `В (&Список)` разрешено.
- `НЕ В (подзапрос)` не заменять механически: отдельно проверить обработку `NULL` и отсутствие соответствий.
- Не соединяться непосредственно с подзапросами в `ИЗ`: предварительно помещать их результат в ВТ.
- Прямое `ЛЕВОЕ СОЕДИНЕНИЕ` с виртуальной таблицей запрещено проектным стандартом. Подготовить результат виртуальной таблицы в ВТ и соединяться с ней. Другие соединения с виртуальными таблицами по возможности также выносить в ВТ.
- Использовать внутреннее соединение, если соответствие обязательно; левое — если нужно сохранить строки без соответствия.
- Предпочитать соединения по равенству ключей. Необходимые диапазонные условия оставлять. Условия из `ПО` переносить в `ГДЕ` только при сохранении результата, особенно для внешних соединений.
- Контролировать кратность соединений. Не устранять размножение строк через `РАЗЛИЧНЫЕ`, пока не проверены ключи и условия соединения.
- Избегать `ИЛИ` в основных условиях, если оно ухудшает план. Заменять его на `ОБЪЕДИНИТЬ ВСЕ` только при сохранении кратности строк и обработки `NULL`. Для альтернативных значений одного поля использовать `В (&Список)`.
- Не разыменовывать составные ссылки без ограничения типа. Реквизиты получать через `ВЫРАЗИТЬ(Ссылка КАК Тип).Реквизит` либо явное соединение с таблицей нужного типа.
- При соединении по ссылкам использовать прямое сравнение: `Источник.СоставнаяСсылка = ТаблицаТипа.Ссылка`. Приведение добавлять только при обоснованной необходимости.
- Конкретный ссылочный тип проверять через `ССЫЛКА`.
- В СКД согласовывать параметры запроса с параметрами схемы, а пользовательские отборы — с полями и условиями компоновки. Проверять, что нужные отборы попали в сформированный запрос и, где допустимо, в параметры виртуальных таблиц.

## Временные и виртуальные таблицы

- ВТ делать узкими: только нужные строки и столбцы. Каждая ВТ должна иметь понятную задачу.
- ВТ менее 1000 записей, как правило, не индексировать. Для больших ВТ, используемых в соединениях или отборах `В (...)`, проверять необходимость индекса по соответствующим ключам. Учитывать стоимость построения и повторное использование; пользу подтверждать замерами.
- В виртуальных таблицах явно задавать необходимые даты или период. Доступные отборы передавать в параметр условия, только если это сохраняет смысл расчета.
- Не считать параметр условия и внешнее `ГДЕ` эквивалентными: первый ограничивает данные расчета, второе фильтрует его результат. Особенно внимательно проверять перенос отборов для срезов и остатков.
- Для регистров бухгалтерии проверять отборы по счетам, корреспондирующим счетам и видам субконто. Учитывать, что параметры субконто определяют состав и порядок полей аналитики.
- Для `ДвиженияССубконто` учитывать наличие неактивных записей. Если нужны только активные проводки, задавать соответствующий отбор.
- Для регистров расчета различать период регистрации, период действия, фактический период действия и базовый период; учитывать вытеснение и настройки зависимости от базы.
- Выбирать только необходимые поля виртуальной таблицы: дополнительные расчетные поля могут вызывать дополнительные соединения и вычисления.
- Периодичность выбирать по требуемой детализации. Поля периода, регистратора и номера строки использовать только при периодичности, которая их предоставляет.
- Проверять доступность полей в параметре условия отдельно от доступности во внешнем запросе. Недоступные там отборы выполнять снаружи.

## Группировки и объединения

- Группировать и удалять повторы после фильтрации, на минимально необходимом наборе полей.
- Состав группировки определять требуемой детализацией результата. Не добавлять реквизиты только ради их вывода.
- Дополнительные реквизиты присоединять после получения итогов или уникальных ключей, если соединение не меняет детализацию и не размножает строки.
- `РАЗЛИЧНЫЕ` применять только для необходимой дедупликации, а не для сокрытия ошибок соединения.
- Предпочитать `ОБЪЕДИНИТЬ ВСЕ`, если удаление повторов не требуется. Дедупликацию внутри веток и между ними выполнять только по смыслу результата.
- Ветки объединения должны иметь одинаковое число столбцов с одинаковым назначением по позициям. Типы приводить только при необходимости; разные типы могут образовать составной тип результата.
- `ВЫБОР` в группировке не запрещать автоматически. Выносить вычисление в отдельную ВТ, если это упрощает запрос или подтвержденно ускоряет его.
- Строки неограниченной длины перед сравнением при необходимости приводить через `ВЫРАЗИТЬ(... КАК СТРОКА(N))`. Не допускать усечения, меняющего результат; если безопасное приведение невозможно, выбрать другой способ сравнения.

## Оформление проекта

- Текст начинать с новой строки после `Запрос.Текст =`; не добавлять общий отступ ко всем строкам запроса.
- Использовать осмысленные полные имена ВТ и псевдонимов. Сокращения вроде `ШР`, `ПОД`, `КИ` не использовать.
- Не допускать совпадение псевдонимами таблиц и именами ссылочных полей. Пример: вместо `Справочник.Номенклатура КАК Номенклатура` используй: `Справочник.Номенклатура КАК СправочникНоменклатуры`.
- Выбираемым полям явно задавать псевдонимы через `КАК`.
- Результат сохранять в переменную: `РезультатЗапроса = Запрос.Выполнить()` или `РезультатыПакета = Запрос.ВыполнитьПакет()`.

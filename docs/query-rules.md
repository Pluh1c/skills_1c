# Создание и оптимизация запросов 1С

Единственный владелец правил и техник запросов, включая запросы наборов СКД. Особенности настройки отчета — [СКД](1c-skd.md); свидетельства приемки — [query-review.md](query-review.md).

## До написания

1. Проверить через RLM метаданные, имена/типы полей, существующие запросы и разрешенный API подсистемы.
2. Описать ключ результата, нужную кратность строк, дубли, пустые ссылки и `NULL`, период и права пользователя.
3. Выбрать минимальные поля и ранние отборы. Запрос по коллекции ключей выполнить одним пакетом вне цикла.
4. Для оптимизации сохранить исходный результат/замер/план; без runtime обоснование остается статической гипотезой.

## Рецепт пакетного чтения

Сначала получить уникальные нужные ключи, затем присоединить данные по этим ключам. При замене проверки `В (подзапрос)` соединением уникальность ключей сохраняет семантику принадлежности и предотвращает размножение строк.

```bsl
// Данные - таблица значений с типизированной числовой колонкой Ключ.
// Для примера нужны только положительные ключи; реальные отборы задает контракт.
Запрос = Новый Запрос;
Запрос.Текст =
"ВЫБРАТЬ
|    Данные.Ключ КАК Ключ
|ПОМЕСТИТЬ ВТ_Ключи
|ИЗ
|    &Данные КАК Данные
|ГДЕ
|    Данные.Ключ > 0
|СГРУППИРОВАТЬ ПО
|    Данные.Ключ
|;
|
|ВЫБРАТЬ
|    Ключи.Ключ КАК Ключ
|ИЗ
|    ВТ_Ключи КАК Ключи";
Запрос.УстановитьПараметр("Данные", Данные);
РезультатЗапроса = Запрос.Выполнить();
```

Пример формы пакета, не требование создавать ВТ для каждого простого чтения. Входная таблица в примере не требует конкретного справочника; группировка делает ключи уникальными. В реальном запросе заменить источник подтвержденными метаданными либо таблицей ссылок с типизированной колонкой. Отбор положительных чисел относится только к демонстрационным ключам.

## Соединения, фильтры, типы

- Соединять по полному ключу и нужной кратности. `ВНУТРЕННЕЕ` — нужны совпадения; `ЛЕВОЕ` — нужны также строки без соответствия. До тяжелой группировки сокращать набор и поля.
- Для левого соединения ограничение правой стороны в `ПО` сохраняет строки без совпадения; то же условие в `ГДЕ` может их исключить. Перенос разрешен только при доказанно нужной семантике; `NULL` обработать явно.
- Прямую навигацию `Таблица.Ссылка.Реквизит` заменить явным соединением. Для реквизита составной ссылки использовать явно типизированное `ВЫРАЗИТЬ(... КАК Тип).Реквизит`; для соединения достаточно сравнения ссылки с `ТаблицаТипа.Ссылка`.
- Тип составного реквизита ограничивать `ССЫЛКА`. Если группировка нужна по типу, группировать только требуемую категорию, не добавлять саму ссылку.
- `ВЫБОР КОГДА` применять для условного поля; условия отбора/соединения выражать булевой алгеброй. Для группировки по вычисляемой категории сначала вычислить ее в промежуточном наборе.
- Полям задать `КАК`, источникам — предметные алиасы; алиас присоединенной таблицы отличать от имени реквизита другой таблицы.
- Если нужен только текст, рассмотреть `ПРЕДСТАВЛЕНИЕ()`; проверить сортировку, локализацию и влияние на выборку.
- Для длинной строки использовать ключ или сравнимое значение с допустимой длиной. Приведение строки допустимо только при сохранении смысла: усечение разных исходных значений не должно делать их равными.

## Виртуальные таблицы

Проверить сигнатуру конкретной виртуальной таблицы установленной платформы; позиционные параметры различаются. У накопления `Остатки`, `Обороты`, `ОстаткиИОбороты` разные списки параметров — правила «3-й/4-й для всех» нет.

Отборы измерений проталкивать в параметры, когда это сохраняет результат. Периодичность выбрать так, чтобы нужные поля регистратора/периода были доступны дальше. До тяжелой виртуальной таблицы собрать минимальный набор ключей и ограничить источник ими. Сложную проверку типа выполнять в том месте, где ее поддерживает именно выбранная таблица; неизвестную допустимость выражения проверить, не утверждать общий запрет `ССЫЛКА` во всех параметрах.

ВТ из виртуальной таблицы нужна при повторном использовании, большой стороне соединения или плохом плане; прямое соединение допустимо при подходящем объеме/плане. Пользовательский отбор СКД не считать доказательством ограничения источника в СУБД.

## ВТ и индексы

ВТ содержит поля связи и используемые далее значения; убрать мертвые промежуточные наборы. Малую одноразовую ВТ оставить без индекса. Более 10 000 строк, повторное использование или тяжелое соединение — местные триггеры анализа, не приказ индексировать.

Сравнить стоимость построения индекса и повторных сканирований; индекс начать с полей фактического доступа, при необходимости расширить ключ. У существующего составного индекса учитывать ведущую непрерывную часть; окончательный выбор подтвердить планом. Индекс метаданных оценивать также по стоимости записи и другим потребителям. Индексировать все поля автоматически не требуется.

## Локальные соглашения ИСТК

Это ограничения проекта; платформа допускает некоторые альтернативы. При невозможности сохранить семантику сначала зафиксировать конфликт, а не менять результат ради формального правила.

| Соглашение | Правильный путь / граница |
|---|---|
| Подзапросы вне `ИЗ` не применять; исключение — параметры виртуальной таблицы | `ПОМЕСТИТЬ` + соединение с уникальными ключами |
| `ИЛИ` избегать при эквивалентной замене | Непересекающиеся ветви `ОБЪЕДИНИТЬ ВСЕ`; для пересекающихся сначала обеспечить исходную кратность |
| `РАЗЛИЧНЫЕ` и `ОБЪЕДИНИТЬ ВСЕ` не смешивать | Дедупликация отдельным шагом на минимальном наборе |
| Ветки объединения одинаковой структуры и типов | Выровнять реально различающиеся типы; лишнее `ВЫРАЗИТЬ` не добавлять |
| Неравенства в условии соединения не применять | Соединить по ключам, прочее отфильтровать на малом наборе только при сохранении семантики; для внешнего/интервального соединения требуется отдельное согласованное решение |
| Запрос вне цикла | Пакет по входной коллекции, дальнейшая обработка результата в памяти |
| Текст с новой строки после `Запрос.Текст =`, без дополнительного отступа | Формат примера выше; осмысленные имена ВТ и псевдонимы |
| Результат в промежуточную переменную | `РезультатЗапроса = Запрос.Выполнить()`; обходить выборку без отдельной проверки пустоты, если она не нужна контракту |

## Проверка

Сравнить ключи, количество строк и значения: пустой источник, отсутствующая правая строка, несколько совпадений, `NULL`, границы периода, составной тип, пересечение ветвей. Проверить права/RLS и СКД-итоги отдельно. Статическая проверка не доказывает ускорение: время, чтения, план и пиковую память сравнить в runtime на сопоставимых данных.

# Полный анализ состава подсистемы через RLM

Читать только для полного перечня/отчета по подсистеме. Основной порядок: [rlm-workflow.md](rlm-workflow.md). Источник: [AGENT_INSTRUCTIONS](https://github.com/Dach-Coin/rlm-tools-bsl/blob/master/docs/AGENT_INSTRUCTIONS.md), адаптировано 2026-10-03.

1. Найти точную строку analyze_subsystem по имени/синониму и файлу. Одно имя может вернуть несколько подсистем; их составы не суммировать без явного основания.
2. Для direct-строки match=name|synonym брать raw_content только при content_truncated=False и len(raw_content)=objects_returned=total_objects. Дополнительно проверить subsystems_found=len(subsystems): output-cap может убрать целые строки.
3. Строка match=content содержит совпавшие ссылки, а не полный состав. Перейти к точному имени подсистемы.
4. При усечении следовать hint: увеличить limit, если ограничение не output-cap; при output-cap читать Content из XML по file. Для старого контракта без доказуемых признаков полноты также сверить XML.
5. Неусеченность транспорта не доказывает разбор каждого XML корня: malformed/unparsed файлы могут быть пропущены. Отдельно проверить границу расширений; current-root-only не называть эффективным составом базы со всеми расширениями.
6. Программно посчитать M по выбранному raw_content либо Content/xr:Item точного XML. Сгруппировать по типам; итог отчета и сумма по типам должны совпасть с M. При расхождении исправить перечень. Повторное чтение того же XML без причины не нужно.
7. Отделить участников состава от используемых связанных объектов. Для полного отчета покрыть каждый элемент состава; типы и ключевую логику подтверждать структурой/телами методов. Подписки и движения фильтровать по целевому срезу.
8. В отчете указать источник, границы охвата, итог и результат сверки. Частичный перечень обозначить как N из M; если M неизвестно, не выдумывать знаменатель.

Фиксированная фраза «СВЕРКА ОК», полный шаблон отчета и повышенные лимиты не требуются для обычной навигации.

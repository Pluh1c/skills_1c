# Правила работы со скиллами архива

Свод правил для агента, использующего скиллы этого архива. Дополняет `README.md`;
предметные нормы 1С живут в самих скиллах и их `references/`/`reference/`.

## Маршрутизация по скиллам

- Типовой цикл: `*-info` → `*-compile` / `*-edit` / `*-add` / `*-remove` → `*-validate`.
- Метаданные, формы, СКД, MXL, роли, подсистемы, XDTO, EPF/ERF, базы, веб — только
  соответствующий скилл; XML руками не писать.
- Создание новой сущности — `*-compile`/`*-init`; точечная правка — `*-edit`;
  полный разбор — `*-dump`/`*-decompile`.
- Перед применением прочитать `SKILL.md` скилла целиком; `references/`/`reference/` —
  лениво, по прямой необходимости.
- Диагностика расширений — `cfe-*`; захват/заимствование — `cfe-borrow`/`cfe-patch-method`.

## Вызов скриптов

- Скиллы размещаются в `.opencode/skills/<имя>/scripts/`.
- Запуск: `powershell.exe -NoProfile -File ".opencode/skills/<имя>/scripts/<скрипт>.ps1" ...`
  либо Python-вариант (`.../<скрипт>.py`), если он есть в скилле.
- Пути к платформе 1С и базам — из `.v8-project.json` (`v8path`, `databases[]`),
  не хардкодить пути `Program Files`/диска.

## Конвенции файлов

- 1С: сохранять CRLF; XML-выгрузка — UTF-8; BOM — как в исходниках проекта.
- В идентификаторах 1С `ё` запрещена — использовать `е`.
- UUID и прочие права существующих объектов не терять при точечной правке:
  применять `*-edit`, а не пересоздавать объект.
- Внешние обработки/отчёты размещать в `Внешние отчеты и обработки/`.

## Верификация

- После правки метаданных/форм/ролей/СКД/макетов — запускать парный `*-validate`.
- Условие завершения — ноль ошибок severity 1.
- Ошибка в значении операции — отказ до записи: файл не меняется.

## Деструктивные операции

- `db-load-*`, `db-dump-*` по живой базе, `meta-remove`, `form-remove`, `template-remove` —
  только после явного подтверждения.
- Перед массовым удалением (>10 файлов) вывести список и запросить подтверждение.
- Секреты (`.env`, токены, ключи) не коммитить; при просьбе — предупредить о рисках.

## Границы

- Пути и параметры, специфичные для машины (vault Obsidian, пути к MCP), задавать
  в `restore.local.json` и `opencode.jsonc.tpl`, а не внутри скиллов.
- Runtime-проверки, требующие собранного контура 1С, фиксировать как отложенные,
  если контур недоступен.

# Чек-листы ревью BSL-кода и метаданных 1С

> **Provenance:** адаптировано из `SPEC-001-framework-architecture.md` (чек-листы ревьюера) и `yellow-hammer-dev-rules-analysis.md` репозитория [SteelMorgan/1c-agent-based-dev-framework](https://github.com/SteelMorgan/1c-agent-based-dev-framework). Статус: **adapted** (2026-08-04). Полный реестр заимствований — [external-borrowings.md](external-borrowings.md).

Статическое ревью — основной инструмент верификации, пока недоступен тестовый контур (см. `verification-plan.xml`, `runtime-status: deferred`). Проверки выполняются по diff после каждого кейса.

Нормы разработки принадлежат [общему маршруту](1c-standards.md); здесь свидетельства приемки, не второй стандарт.

## 1. Чек-лист BSL-кода

### Компиляция и контекст
- [ ] Правильная директива компиляции: `&НаСервереБезКонтекста` для функций без контекста формы; `&НаСервере` только если нужен контекст
- [ ] Клиентские методы не обращаются к серверным данным напрямую (через `ВызовСервера`)
- [ ] `&НаКлиенте` методы не содержат тяжёлых запросов
- [ ] `&НаСервереБезКонтекста` процедуры не используют реквизиты формы

### Дата и время
- [ ] `ТекущаяДатаСеанса()` вместо `ТекущаяДата()`
- [ ] Смысл сравнения дат и включение границ периода соответствуют контракту операции

### Обработка ошибок
- [ ] Ожидаемая ошибка обработана по контракту [метода](1c-methods.md), неожиданная передана выше; журнал разрешен только по [logging owner](../skills/istk-rules/references/logging-strategy.md)
- [ ] В `Исключение` нет пустого тела
- [ ] Нет блокировки транзакций на время длинных операций

### Запросы
- [ ] Запросы не вызываются в циклах (нет N+1)
- [ ] `Запрос.Текст` задаётся до `УстановитьПараметр`
- [ ] `Выполнить()` вызывается один раз, результат не дёргается повторно без причины
- [ ] Нет `РезультатЗапроса.Пустой()` перед обходом, когда достаточно `Выбрать()`
- [ ] Временные таблицы с осмысленными именами (`вт_`/`ВТ_`)
- [ ] Полные правила — в [query-review.md](query-review.md)

### Общие правила
- [ ] Именование по стандартам ИТС (нет `ё`, нет транслита, префикс `но` для новых объектов)
- [ ] Связанные параметры имеют понятный контракт по [руководству методов](1c-methods.md); число аргументов не подменяет ответственность
- [ ] Логика отделена от UI: модули формы тонкие, бизнес-логика в общих модулях/объектах
- [ ] `УстановитьПривилегированныйРежим(Истина)` только в явных границах, без обхода прав без нужды

## 2. Чек-лист формы (управляемые формы)

- [ ] Команды, меняющие данные, имеют «Изменяет сохраняемые данные»
- [ ] Заголовок формы через «ПутьКДаннымЗаголовка», а не жёстко в коде
- [ ] «Проверка заполнения» на реквизитах с обязательностью
- [ ] Видимость/доступность элементов устанавливается централизованной процедурой (последним действием после заполнения)
- [ ] «Группа пользовательских настроек» для отчётов/списков
- [ ] Обработчики именованы по соглашению (`ИмяПриИзменении`, `ИмяПриВыборе`)

## 3. Чек-лист метаданных (Yellow Hammer)

### Справочник
- [ ] Иерархия включена только при необходимости; владелец/предок осмысленны
- [ ] Код серии, длина кода, контроль уникальности
- [ ] ТЧ не используются там, где нужен отдельный объект

### Документ
- [ ] Нумерация (период, автонумерация) и контроль дублей
- [ ] Проведение: `ОбработкаПроведения` формирует движения только при изменении данных
- [ ] `ОтменаПроведения` корректна, движения снимаются полностью
- [ ] Реквизит «Только просмотр»/блокировка редактирования после проведения (если нужно)

### Регистр
- [ ] Регистр накопления — остатки или обороты (выбран верный вид)
- [ ] Регистр сведений — периодичность и режим записи (независимый/подчинённый регистратору)
- [ ] Размерности не содержат избыточных дублей (контроль уникальности записей)

### Отчёт/СКД
- [ ] Параметры с типом и значением по умолчанию
- [ ] Вариант по умолчанию определён; пользовательские настройки сохраняются
- [ ] Расшифровка и экспорт работают (стандартные механизмы СКД)

### Роль и права
- [ ] RLS задан через шаблоны, а не копированием текста
- [ ] Право «Чтение» у всех ролей, которым нужно; лишних прав нет

## 4. Чек-лист внешних отчётов/обработок

- [ ] БСП-регистрация: `СведенияОВнешнейОбработке` с ID и командой (см. `epf-bsp-init`)
- [ ] Safe mode выключен только при явной необходимости
- [ ] Отчёт на СКД: вычисления в запросе, модуль минимальный
- [ ] Версия/дата в имени каталога (`но_Имя_ГГГГ.ММ.ДД`)
- [ ] `main/Внешние отчеты и обработки/` — правильный каталог

## 5. Формат замечаний

```
[BLOCK|WARN|INFO] <файл>:<строка или блок> — проблема — рекомендуемое исправление
```

- **BLOCK** — обязательное исправление до merge (ошибка, потеря данных, нарушение прав)
- **WARN** — риск/запах, исправить в этом кейсе или задокументировать
- **INFO** — рекомендация, не блокирует

Связь замечаний с модулями и верификацией — `docs/verification-plan.xml` (`V-M-*`, `AutonomyReadiness`).

## 6. Ревью-протокол (scope-изоляция)

> **Provenance:** адаптировано из `framework/subagents/reviewer.md` + `self-recovery-limits` репозитория SteelMorgan. Статус: **adapted** (2026-08-04).

Ревью выполняется изолированно от автора (свежий контекст/сессия) и **не исправляет** найденное — только выдаёт вердикт.

Обязательные pre-steps до ручного анализа:
1. `git diff` — точный объём изменений
2. Карта вызовов (LSP `incoming/outgoing-calls` или RLM) — что затрагивает изменение
3. Диагностика (1c-check / LSP) — механические ошибки, чтобы не тратить ручной анализ
4. Затем — чек-листы §1-§4 по затронутым областям

Правила:
- Ревью по одному scope за проход (spec / metadata / code / query / form / tester)
- Каждый факт, подтверждённый только чтением кода без прогона, помечается `[UNVERIFIED]` (runtime недоступен)
- Вердикт: `PASS` / `REVIEW_BLOCK` (требуется переделка) / `REVIEW_WARN`
- BLOCK-итераций на scope — максимум 3; после исчерпания — эскалация оператору
- Ревьюер не слабее автора (см. `docs/agent-ops.md` §2); для независимости допустим **Codex CLI** (`codex exec`, read-only) — см. `docs/capability-map.md` §5
- Формат замечаний — §5 (BLOCK/WARN/INFO)

## 7. Анти-паттерны 1С (готовый BLOCK-чек-лист)

> **Provenance:** из `framework/rules/*` и review-навыков SteelMorgan. Статус: **adapted** (2026-08-04).

- [ ] Запросы в цикле (N+1) — вынести в один запрос/пакет
- [ ] Обращение к регистру через `РегистрыНакопления.X.ПолучитьОстатки()` в цикле
- [ ] Отсутствие `РАЗРЕШЕННЫЕ` в запросе там, где нужен RLS-safe доступ
- [ ] `УстановитьПривилегированныйРежим(Истина)` без снятия (BLOCK, см. `1c-bsp-patterns.md`)
- [ ] HTTP-запрос без таймаута (`HTTPСоединение` без времени ожидания)
- [ ] Временные файлы без `ПолучитьИмяВременногоФайла()` и без удаления после использования
- [ ] Клиент/сервер context-ошибки: обращение к реквизитам формы в `&НаСервереБезКонтекста`; передача мутабельных объектов через границу
- [ ] `ТекущаяДата()` вместо `ТекущаяДатаСеанса()`
- [ ] Прямая правка `*.xml`/`*.mxl` метаданных текстовыми инструментами (Edit/sed/Python) — только через xml-генерацию/скиллы
- [ ] Комментарием «заглушить» код вместо удаления — комментировать только с маркером причины

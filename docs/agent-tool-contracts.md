# Контракты инструментов: границы доказательства

Читать при неполном/ошибочном ответе инструмента, проверке результата изменения или заимствовании upstream workflow. Для обычной навигации достаточно выбранного skill; этот файл не глобальный обязательный контекст.

## Ответ и проверка

- «Запущено»/«принято» не означает «выполнено». Если инструмент вернул задание, получить конечный результат способом, объявленным его текущей схемой.
- Проверка успешна, когда проверен нужный объект, анализ завершился и результат удовлетворяет критерию соответствующего skill. Пустая диагностика при недоступном провайдере, timeout или partial не доказывает успеха.
- Отличать ошибку операции, неполный результат и найденную проблему исходника. Исправлять причину или обозначать непроверенную часть; не превращать отказ в чистый отчёт.
- После изменения проверить нужный вид артефакта matching validate/1c-check, а фактический эффект — targeted read/diff. Статическая проверка не доказывает runtime; требования уже заданы AGENTS и выбранным skill.

## Полнота и контекст

- Размер страницы, предел полученного окна и охват источника — разные ограничения. Последняя страница не доказывает полноту поиска при квоте/пропусках провайдера. Полный список и отсутствие требуют доказанного охвата; подробности RLM — [rlm-workflow.md](rlm-workflow.md).
- Продолжать страницы только если они нужны для вывода. При stale cursor повторить запрос; при неполном окне сузить предмет или проверить первоисточник разрешённым способом. Не переносить поля Unica на локальный MCP: читать фактическую схему и доступные признаки ответа.
- Найти объект/метод → прочитать нужный диапазон → проверить утверждение. Целый модуль, каталог справки и дополнительные references загружать только если узкого чтения недостаточно.

## Изменения

- Определить цель, разрешённый корень и затронутые файлы до записи. Пользовательское поручение разрешает его объём; preview не создаёт нового разрешения. Деструктивные действия регулирует AGENTS.
- Если выбранный инструмент поддерживает preview/plan, использовать его для сложной или рискованной правки. Сверить цель и эффекты перед исполнением. Preview сам по себе не фиксирует состояние: после внешнего изменения повторно проверить входы.
- Не обещать атомарность, rollback или защиту от устаревших входов, если выбранный скрипт/инструмент их не гарантирует. При unsupported/unavailable не выдумывать аргументы; выбирать поддержанный локальный маршрут в пределах поручения или обозначить блокировку.

## Происхождение

- Для заимствования фиксировать repository, commit, исходный path, лицензию и локальную адаптацию в [external-borrowings.md](external-borrowings.md) либо связанном manifest. Проверять первичный origin, чтобы одинаковый компонент не обновлять из двух портов.
- В API-выводе различать справку платформы, стандарт разработки и прикладной код. Указать применимую версию и контекст, когда они влияют на вывод. Поисковый snippet не равен прочитанному документу.

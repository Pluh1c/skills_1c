# События объектов и управляемых форм

Применять при обработчике, записи/проведении, подписке или привязке события. Директивы и серверные границы принадлежат [контекстам](1c-contexts-and-modules.md), размещение повторяемого алгоритма — [методам](1c-methods.md).

## Выбор владельца логики

| Сценарий | Обработчик / механизм | Что выполнить |
|---|---|---|
| Первичное заполнение, ввод на основании | `ОбработкаЗаполнения` объекта | Использовать данные основания; сформировать новый объект |
| Копирование | `ПриКопировании` объекта | Очистить значения, которые не должны переходить в копию |
| Условная/составная обязательность | `ОбработкаПроверкиЗаполнения` объекта | Проверить зависимости полей/строк, сообщить причину отказа |
| Подготовка и инварианты записи при любом вызове | `ПередЗаписью` объекта | Подготовить реквизиты, проверить состояние до записи |
| Данные, связанные с выполненной записью | `ПриЗаписи` объекта | Обновить связанные данные в транзакции; записанный объект уже не менять |
| Движения и ограничения проведения | `ОбработкаПроведения` | Создать движения, проверить допустимость проведения; черновик остается записываемым |
| Отмена проведения | `ОбработкаУдаленияПроведения` | Обработать отмену в соответствии с моделью движений |
| Подготовка удаления | `ПередУдалением` объекта | Проверить/подготовить связанные данные |
| Первичное построение управляемой формы | `ПриСозданииНаСервере` | Прочитать объявленные параметры формы, добавить/настроить элементы |
| UI после открытия | `ПриОткрытии` | Клиентское взаимодействие |
| Действие UI при записи / после записи | `ПередЗаписью` / `ПослеЗаписи` формы | Клиентская часть; надежность записи обеспечивает объект |
| Подготовка объекта из данных формы | `ПередЗаписьюНаСервере` формы | Работать с `ТекущийОбъект`; это отдельный этап от объекта |
| Связанная серверная работа при записи формы | `ПриЗаписиНаСервере` / `ПослеЗаписиНаСервере` | Выбрать этап по потребности в транзакции и уже выполненной записи |

Сигнатуры зависят от типа объекта/расширения формы. Таблица — выбор ответственности, не универсальный шаблон параметров.

## Последовательность: фиксировать сценарий

Для успешной обычной записи документа из управляемой формы, без проведения, отказов и дополнительных программных записей, основной маршрут:

`ПередЗаписью` формы (клиент) → серверная подготовка/проверка заполнения → `ПередЗаписьюНаСервере` формы → `ПередЗаписью` объекта → запись объекта → `ПриЗаписи` объекта → `ПриЗаписиНаСервере` формы → `ПослеЗаписиНаСервере` формы → `ПослеЗаписи` формы (клиент).

Это основной путь, не полная трасса. Проверка заполнения имеет собственные обработчики объекта и формы; она не становится автоматически частью любого программного `Объект.Записать()`. Для программной записи требуемую проверку вызвать явно по контракту операции. Проведение/отмена добавляют соответствующие обработчики и работу с движениями; исключение/`Отказ` обрывают дальнейший путь. При внешней транзакции успешная запись еще не означает итоговый commit. Подписки и перехватчики расширений учитывать отдельно; на порядок нескольких независимых подписок не опираться. Обычная форма — другой жизненный цикл.

Рецепт: определить точку входа (форма, фон, обмен, прямой вызов), режим записи, тип объекта и внешнюю транзакцию; найти обработчики, подписки и перехватчики через RLM/LSP; составить маршрут конкретного сценария; проверить трассой в тестовой базе. UI после записи помещать в `ПослеЗаписи`; действия, требующие подтвержденного commit, планировать с учетом владельца транзакции.

## Проверка заполнения и отказ

Для обязательных реквизитов наших объектов задать `FillChecking = ShowError`. В обработчике оставить условные, межреквизитные и табличные проверки. Для условного исключения из штатной проверки удалить имена из `ПроверяемыеРеквизиты`; обязательность остается описанной метаданными. При обменной загрузке локальные проверки ИСТК пропустить. Ошибки отдельных полей сообщать отдельно через проверенный БСП API с путем `Объект.<Реквизит>`; политика сообщений — [1c-rules.md](1c-rules.md).

`Отказ` наращивать: при обнаружении ошибки присвоить `Истина`, сохранив предыдущий отказ. Для `СтандартнаяОбработка` смысл иной: собственная реализация отключает стандартную через `Ложь`; обратно ранее отключенную обработку автоматически не включать.

```bsl
// Фрагмент обработчика проверки; ОшибкаЗаполнения вычислена отдельно.
Если ОшибкаЗаполнения Тогда
	Отказ = Истина;
	// Сообщить конкретную причину через проектный БСП API.
КонецЕсли;
```

`ОбменДанными.Загрузка` проверить первым в `ПередЗаписью`, `ПриЗаписи`, `ПередУдалением` и соответствующих подписках; при загрузке вернуть управление. Подписка использует свой параметр источника, а не переменную модуля объекта. Обоснованное исключение обменного механизма документировать; код загрузки отвечает за целостность пропускаемых инвариантов.

## Привязка и повторное использование

Статическое событие формы привязать к процедуре в `Form.xml`; совпадения имени процедуры недостаточно:

```xml
<Events>
  <Event name="OnOpen">ПриОткрытии</Event>
  <Event name="OnCreateAtServer">ПриСозданииНаСервере</Event>
</Events>
```

Для динамического элемента привязать через `УстановитьДействие`; отсутствующая запись в XML тогда штатна. Для подключаемых обработчиков применять узнаваемый префикс `Подключаемый_`. Обработчик события не вызывать вместо обычного метода: выделить алгоритм и вызвать его из обоих мест. Области формировать по реально существующим событиям формы, элементов, таблиц, команд и служебным методам; пустые обязательные области не создавать.

Для расширения события заимствованной формы привязка `Before`/`After`/`Override` задается `callType` в XML. Для перехвата метода модуля применять соответствующую аннотацию расширения. `&Вместо` допустима и для процедур, и для функций: сохранить исходный вызов через `ПродолжитьВызов`, если задача не требует осознанной полной замены. Сигнатуру/способ перехвата проверить matching skill; аннотация расширения не заменяет директиву исполнения.

Обработчики `НачалоВыбора` и `ПриАктивизацииСтроки` требуют особой проверки допустимых серверных вызовов: для нужной работы использовать серверный метод без контекста с явными параметрами, а контекст формы там не предполагать.

## Проверка

Статически проверить binding, сигнатуру, подписки, сохранение отказа, обмен и ответственность. После кода — BSL-LS; после XML — matching form/meta validate. Runtime-сценарии: запись формы и программная запись, проведение и черновик, отказ, обмен, копирование, несколько подписок; фиксировать фактическую последовательность и rollback, а не выводить их из названий событий.

Основание: справка событий установленной платформы; [стандарт серверных вызовов](https://kb.1ci.com/1C_Enterprise_Platform/Guides/Developer_Guides/1C_Enterprise_Development_Standards/Client_server_interaction/Server_call_optimization/?language=en). Unica `object-events`/`form-events` адаптированы, ошибочное обобщение `Отказ` на `СтандартнаяОбработка` исключено. [Provenance](external-borrowings.md).

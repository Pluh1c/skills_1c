# Проектирование СКД и передача параметров

Применять при изменении смысла отчета, наборов, ресурсов, параметров, вариантов или программной компоновки. XML/DSL операции — matching `skd-*` и [skd-guide.md](skd-guide.md); текст запроса — [query-rules.md](query-rules.md). Правила запроса здесь не копируются.

## Рецепт структуры отчета

1. Описать строки, группировки, требуемые итоги, права и пользовательские настройки.
2. Выбрать набор: `Запрос` для данных базы; `Объединение` для независимых совместимых наборов; `Объект` для уже вычисленных/внешних данных, когда запрос не подходит. Для объекта оценить память и потерю проталкивания отбора.
3. Поле запроса использовать в соединении/отборе/группировке; ресурс — для агрегата; вычисляемое поле — для представления/производного значения. Проверить смысл итогов: построчное выражение не равно ресурсу.
4. Оставить штатную компоновку, расшифровку, пользовательские настройки и условное оформление. Самостоятельный вывод выбирать только при конкретной нехватке штатного механизма.
5. Другую структуру оформить вариантом; другой фильтр — настройкой. Быстрые настройки — часто изменяемые; служебные параметры скрыть.

## Цепочка параметра

`реквизит/параметры отчета → эффективные настройки СКД.ПараметрыДанных → объявленный параметр схемы → &Имя в запросе набора`.

Параметр формы, параметр выбора, пользовательский отбор и параметр запроса — разные сущности. Совпадение имен не передает значение автоматически. В схеме объявить имя, тип и допустимость пустого значения; в запросе использовать это же имя; в коде передать значение в параметры данных. Обязательность задать только когда пустое значение не имеет корректного смысла.

| Роль параметра | Кто владелец значения | Как применить |
|---|---|---|
| Пользовательский | Вариант + сохраненные/быстрые настройки | Получить эффективные настройки; пользовательское значение сохранить |
| Значение по умолчанию | Инициализация варианта/настроек | Установить до загрузки пользовательского выбора, а не перезаписывать при каждом формировании |
| Вычисляемый служебный | Реквизиты отчета/серверный алгоритм | Рассчитать после загрузки выбора и установить перед созданием макета |
| Фиксированное ограничение | Фиксированные настройки/контракт отчета | Проверить пересечение с обычными настройками; RLS сохраняется отдельно |

`КомпоновщикНастроек.ПолучитьНастройки()` возвращает копию с примененными пользовательскими и фиксированными настройками. Пересекающиеся фиксированные параметры/отборы могут вызвать исключение; не подавлять его и не считать фиксированный набор безусловно безопасным «последним победителем».

## Пример: служебная Организация при ручной компоновке

Условия: схема объявляет типизированный параметр `Организация`; запрос содержит `&Организация`; параметр служебный и скрытый; `Организация` — реквизит отчета; нужный вариант и пользовательские настройки уже загружены. Функция ниже — собственный helper в серверном модуле, не встроенный API.

```bsl
Функция НастройкиДляКомпоновки(Знач КомпоновщикНастроек, Знач Организация)
	Настройки = КомпоновщикНастроек.ПолучитьНастройки();
	Параметр = Новый ПараметрКомпоновкиДанных("Организация");
	ЗначениеПараметра = Настройки.ПараметрыДанных.НайтиЗначениеПараметра(Параметр);
	Если ЗначениеПараметра = Неопределено Тогда
		ВызватьИсключение НСтр("ru = 'В настройках СКД отсутствует параметр Организация.'");
	КонецЕсли;
	ЗначениеПараметра.Значение = Организация;
	ЗначениеПараметра.Использование = Истина;
	Возврат Настройки;
КонецФункции
```

Проверить заполненность и тип реквизита до вызова согласно контракту схемы. Возвращенные `Настройки` передать компоновщику макета; повторный `ПолучитьНастройки()` после helper отбросит изменение копии. Одноименного фиксированного/пользовательского параметра здесь нет: его наличие означает другой контракт, который сначала требуется согласовать. Передавать пользовательскую Организацию тем же helper нельзя без решения, чей выбор имеет приоритет.

Для периода пример потока: пользовательский период → вычисленные служебные `ДатаНачала`/`ДатаОкончания` → одноименные параметры запроса. Вычислять границы после получения эффективного пользовательского периода; согласовать включение последнего момента и тип `Граница`/`Дата` с конкретной виртуальной таблицей.

## Штатная и ручная компоновка

Для штатной обработки изменять параметры в реальном компоновщике настроек отчета в предусмотренном этапе до формирования; учесть последующую загрузку вариантов/пользовательских настроек. Изменение отдельной копии ничего не передает штатному механизму. Точную сигнатуру `ПриКомпоновкеРезультата` проверить для модуля объекта отчета/внешнего отчета: одноименное событие другой сущности не доказательство сигнатуры.

Для ручного вывода: в событии отключить `СтандартнаяОбработка` до начала вывода; получить эффективные настройки; применить служебные значения; создать макет именно с ними; инициализировать процессор с данными расшифровки; вывести результат. Порядок вызовов/сигнатуры компоновщика макета и процессоров взять из справки платформы, не копировать межверсионный шаблон. На исключении не возвращать штатный второй вывод; ожидаемую ошибку обработать по контракту, неожиданную передать выше.

В БСП использовать проверенные точки расширения реальной версии подсистемы отчетов; не внедрять независимый жизненный цикл поверх стандартной формы отчета. Двухпроходную компоновку выбирать, если обычного запроса/ресурса недостаточно; оценить стоимость обоих проходов. Top-N требует определенной сортировки и подходящего ограничения набора, а не случайных первых строк.

## Права и приемка

Выполнять отчет с правами пользователя/RLS. Привилегированный режим — только отдельное обоснованное требование, минимальная область и гарантированное восстановление исходного режима при успехе/ошибке; см. [права](../skills/istk-rules/references/bsp-access-rights.md). Большие объектные наборы оценивать по памяти.

Статически: `skd-info` сверяет наборы, параметры, типы, варианты и запрос; `skd-validate` проверяет структуру/ссылки; код — BSL-LS; запрос — [query-review.md](query-review.md). Под тестовой обычной ролью проверить: пользователь изменил параметр; сменил вариант; загрузил сохраненную настройку; обязательное значение пустое; результата нет; итоги/расшифровка корректны. При ручной компоновке проверить фактически переданную копию и отсутствие второго вывода. Runtime без контура — deferred, а не passed.

# Компоновка элементов формы ИСТК

Только локальные UI-соглашения. Структура методов — [методы](../../../docs/1c-methods.md), обработчики/проверка заполнения — [события](../../../docs/1c-events.md), директивы — [контексты](../../../docs/1c-contexts-and-modules.md).

## Изменение типовой формы

Сначала программное расширение формы. При наличии вкладок свои элементы разместить на отдельной вкладке; без вкладок — в группе без заголовка. Имена собственных элементов — с проектным префиксом. Новая форма разделяет шапку и табличные части; базовая ширина ссылочного поля — 27 символов, многострочного комментария — 79, высота — 3, с проверкой реального отображения.

Команда, меняющая сохраняемые данные, имеет соответствующий флаг. Кнопка по умолчанию без картинки; картинку добавлять по UI-требованию.

## Условное оформление формы

Для идентификатора элемента табличного поля в `<dcsset:field>` использовать имя элемента колонки, например `ТаблицаЗаказовКлиентаТекстОшибки`. Это идентификатор формы, а не универсальный путь поля СКД; не переносить правило на поля наборов отчета.

## Табличные данные внешней обработки

Для локального табличного отображения EPF по умолчанию `ТаблицаЗначений`; `ДинамическийСписок` выбирать, если нужны именно его выборка/отбор/постраничная работа. Для просмотра: `ReadOnly = true`, запрет добавления/удаления, `FullTextSearchOnInput = false` на колонках. Открытие ссылочного значения привязать явным обработчиком и использовать проверенный клиентский API показа значения.

XML менять matching form skill; после изменения — matching validate из AGENTS.

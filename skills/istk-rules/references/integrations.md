# Интеграции 1С с внешними системами

Применять для HTTP, REST, SOAP, файлового обмена, очередей и webhook.

## До реализации

- Зафиксировать контракт: endpoint, метод, формат, аутентификация, таймауты,
  идемпотентность, повторы, журналирование, классификация данных.
- Через RLM проверить существующие интеграции и экспортные методы конфигурации.
- По `docs/1c-bsp-patterns.md` проверить готовый механизм БСП. Имена и сигнатуры
  подтвердить LSP/RLM; не писать по памяти.

## Выполнение

- Долгую операцию выполнять через механизм длительных операций БСП. Прямой
  `ФоновыеЗадания.Выполнить()` использовать только при обоснованном отсутствии
  подходящего механизма.
- На клиенте не выполнять синхронный сетевой вызов.
- Таймаут соединения и чтения задавать явно из параметров проекта или констант.
- Сетевой вызов выполнять вне транзакции базы.
- Код ответа и транспортную ошибку преобразовывать в ошибку доменного уровня с
  безопасным диагностическим контекстом.

## Данные и безопасность

- JSON читать/писать платформенными средствами или проверенным API БСП. Не
  собирать JSON конкатенацией строк.
- Форматы дат, точность чисел, кодировка и допустимые `null` согласовать в
  контракте.
- Секреты хранить в защищенном механизме проекта/БСП. Не писать их в код, лог,
  тексты исключений и тестовые фикстуры.
- Изменяющий запрос делать идемпотентным. Хранить ключ операции и статус.
- Повторы ограничивать числом попыток и задержкой. Не повторять бизнес-ошибки и
  прочие заведомо неповторяемые ответы.

## Проверка

- Отдельно проверить сериализацию без сети.
- Проверить успех, таймаут, недоступность, повтор, дубликат, неверную
  аутентификацию и частичный ответ.
- Внешний тестовый endpoint и данные использовать только с разрешения владельца.

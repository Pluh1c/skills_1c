# Программная работа с правами БСП

Применять при создании профилей групп доступа, назначении профилей пользователям
и проверке ролей/RLS. Перед вызовом БСП API найти экспортный метод через RLM/LSP:
сигнатуры зависят от версии БСП и конфигурации.

## Профили групп доступа

- `ПрофилиГруппДоступа.Роли.Роль` хранит ссылку на идентификатор объекта
  метаданных, не строковое имя роли.
- Полное имя роли имеет вид `Роль.<ИмяРоли>`.
- Роли расширений могут храниться в `ИдентификаторыОбъектовРасширений`.
  Прямой запрос только к `ИдентификаторыОбъектовМетаданных` дает неполный набор.
- Для разрешения имен использовать найденный в текущей БСП общий API,
  обрабатывающий основную конфигурацию и расширения. Не переносить имя метода из
  другой версии БСП без проверки.
- После заполнения сравнить число запрошенных и разрешенных ролей. Пропуск роли
  не считать успешным результатом.
- Не включать `ОбменДанными.Загрузка` при обычном создании профиля: это может
  отключить обработчики регистрации профиля и обновление кеша прав.
- Поставляемый профиль не изменять. Создавать отдельный пользовательский профиль.

## Проверки прав

- Разделять проверки роли конфигурации, роли профиля доступа и RLS. Они имеют
  разную семантику.
- Привилегированный режим учитывать явно. Не заменять БСП-проверку вызовом
  `РольДоступна()` без анализа требуемой семантики.
- В методы проверки объектного права передавать ссылку на объект данных, если
  этого требует найденная сигнатура, не объект `Метаданные.*`.
- Проверять сценарий под непривилегированным пользователем. Администратор скрывает
  ошибки RLS.

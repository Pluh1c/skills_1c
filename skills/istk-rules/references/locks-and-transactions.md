# Блокировки и транзакции

Применять для проведения, пакетной записи, изменения нескольких объектов и
разбора конфликтов блокировок.

## Границы транзакции

- В обработчиках записи и проведения учитывать транзакцию, открытую платформой.
  Не открывать и не фиксировать собственную транзакцию внутри обработчика без
  доказанной необходимости.
- Атомарную запись нескольких объектов оформлять транзакцией в вызывающем коде.
- Шаблон явной транзакции: `НачалоТранзакции()`; `Попытка`; изменения;
  `ЗафиксироватьТранзакцию()`; `Исключение`; `ОтменитьТранзакцию()`;
  `ВызватьИсключение`; `КонецПопытки`.
- Не держать транзакцию во время диалога, сетевого вызова, файловой операции,
  длительной операции или ожидания пользователя.
- Большой пакет делить на транзакции по бизнес-атомарности. Не удерживать один
  набор блокировок на тысячи независимых объектов.

## Управляемые блокировки

- Сначала установить блокировку, затем читать проверяемые остатки, затем писать.
- Блокировать данные регистра по ключам, защищающим инвариант. Блокировка
  документа сама по себе регистр не защищает.
- Для набора ключей использовать `ИсточникДанных` и
  `ИспользоватьИзИсточникаДанных`, не цикл отдельных блокировок.
- Для read-modify-write использовать исключительный режим. Разделяемый режим
  выбирать только после анализа совместимости чтения и записи.
- Все транзакции брать несколько блокировок в одном каноническом порядке.
  Порядок фиксировать в проектной документации после подтверждения фактических
  конфликтующих путей.
- Повтор после deadlock не заменяет исправление порядка блокировок.

## Диагностика

- Конфликт ожидания и deadlock различать по технологическому журналу.
- Для подтверждения использовать события `TLOCK`/`TDEADLOCK` и фактическую
  последовательность захвата. Не делать вывод по одному тексту исключения.
- После изменения проверить все пути записи тех же регистров через RLM/LSP.

Точные конструкторы и методы `БлокировкаДанных` проверять через `1c-syntax`.
